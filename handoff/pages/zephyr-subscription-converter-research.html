社区订阅转换方案调研：Zephyr 该怎么支持 sing-box 和更多目标

调研，Zephyr 多内核与订阅转换，9 个工具、9 个在线站点

Researched Nov 19, 2026, 11:35pm

推荐用 Rust 自建转换模块：统一中间表示、多目标输出，只照公开格式自己写，不嵌入现成转换器；sing-box 最小可用约 4 到 6 周。

  • 同一份 17 个节点的样例实测：没有一个现成工具能输出既完整、又能被 sing-box 1.12 以后版本直接加载的配置。
  • Zephyr 是 MIT 许可证，做得最好的几家（subconverter、Sub-Store）是 GPL 或 AGPL，不能移植它们的代码。
  1. 站点几乎都是同一套。清单里的在线站点，能查到的都是 sub-web 前端加 subconverter 后端，或者是 Sublink Worker、SubBoost、Script Hub 的部署。真正的源码只有几家。subconverter
  2. 节点转换 Sub-Store 最准。17 个节点全保留，sing-box 1.12.12 和 1.14.4 都能加载，WebSocket 的 ed=2048 正确转成 early data。但它只出节点，不出策略组、规则和 DNS。Sub-Store
  3. 完整配置没人转对。subconverter 用自己的模板替换掉订阅里的策略组和规则，输出在 1.12 和 1.14 都加载失败；Sublink Worker 把 Clash 的 DNS 键原样塞进 sing-box，整份配置无法加载。Sublink Worker
  4. Zephyr 能明显领先的地方很清楚。保留用户自己的策略组和规则、跟上 sing-box 新版字段、逐节点报清楚丢了什么、完全本地转换、和客户端设置打通。这几项现有工具都做得不好。
  5. 推荐自建，目标数量分阶段追平。第一版做 mihomo、sing-box、链接订阅；第二版加 Surge、Stash、Loon、Quantumult X、Shadowrocket、原版 Clash；第三版补 Surfboard、Egern、V2Ray。ClashR、SSD 这类已经没人用的目标不做。

实测：同一份样例

样例是一份 Clash 配置，用的全是假凭证：17 个节点（SS2022、SS 加 obfs 和 v2ray-plugin、VMess 的 WS/gRPC/H2/HTTP、VLESS Reality Vision 和 WS、Trojan gRPC、带端口跳跃的 Hysteria2、TUIC、AnyTLS、WireGuard、SSH、SOCKS5、HTTP），select、url-test、fallback、load-balance 和带 filter 的组，16 条规则（含 GEOSITE、RULE-SET、AND、PROCESS-NAME），fake-ip DNS 和 TUN。mihomo 1.19.34 能直接加载这份样例。所有转换都在本机跑，没有发到任何在线站点。

每个项目

Sub-Store节点解析和输出最全最准，只做节点。
  • 核心在 backend/src/core/proxy-utils：parsers/index.js（3242 行）有 50 个解析器，覆盖 URI、Clash、Surge、Loon、QX 写法，Surge、Loon、QX 用 peggy 语法文件解析；producers/sing-box.js 1713 行。
  • 预处理器会先认 HTML 错误页、Base64、SSD、完整 Clash 配置，再逐行解析。测试有 812 个用例。
  • 值得借鉴：多写法解析、ws 的 ed 转 early data、H2 转 sing-box 的 http 传输、转不了就逐节点报错。要避开：没有策略组、规则和 DNS 转换；需要 Node 运行时；AGPL。
Sublink Worker唯一按 sing-box 版本（1.11、1.12、1.14）分别输出的，但实测输出加载不了。
  • 核心：src/builders/SingboxConfigBuilder.js（639 行）、ClashConfigBuilder、SurgeConfigBuilder，解析器只有 7 种分享链接加 Clash YAML。规则用 rule_set 远程拉 .srs。测试 39 个文件、239 个用例。
  • 值得借鉴：按版本切换输出、用 rule_set 而不是 geosite、MIT 可以直接参考甚至拷代码（保留版权声明）。
  • 要避开：把源格式的字段原样塞进目标格式（dns 键、plugin_opts 对象、h2 传输名）；fallback 和 load-balance 降成 select 却不提示。
subconverter 及分支目标最多、用户最多，sing-box 输出落后两个大版本。
  • 核心：src/parser/subparser.cpp（3522 行）解析，src/generator/config/subexport.cpp（3159 行）输出，ruleconvert.cpp 转规则。原版的 sing-box 输出缺新协议，分支补上了 VLESS、Hy2、AnyTLS。
  • 它的定位是「订阅只提供节点，策略组和规则来自远程模板」，所以订阅里自带的组和规则一律丢掉。sing-box 规则还在写 geoip、geosite 字段，DNS 还是旧格式。
  • 值得借鉴：目标清单和每个客户端的写法差异。要避开：静默丢节点、模板替换用户配置；GPL，不能移植。
ConfigFlowMihomo、Surge、MosDNS 配置生成器，节点靠 Sub-Store。
  • 后端 Python（backend/converters），前端 Vue，MIT。不出 sing-box。
  • 值得借鉴：规则交付方式的测试（比如 classical 规则集的生成），配置生成的结构。
SubBoost可视化 Clash/Mihomo 配置，输入容错做得认真。
  • TypeScript monorepo（packages/core、server-core、ui），只做 Clash/Mihomo，代码里没有 sing-box。测试有 1434 个用例。
  • 值得借鉴：parser 里专门的 limits.ts 和 yaml-syntax-budget.ts，给输入大小和 YAML 复杂度设上限。AGPL，只能参考思路。
Script Hub、SubCase、Sub-Store 前端不在订阅转换的范围里。
  • Script Hub（GPL-3.0）做 QX、Surge、Loon、Stash 之间的模块和覆写转换；SubCase（AGPL-3.0）是 Sub-Store 的安卓封装；Sub-Store 前端是 GPL-3.0 的 Vue 界面。按你的范围，这些都不作为目标。
clash2sing-box 和 clash2singbox专门的 Clash 转 sing-box 工具，都不能直接用。
  • clash2sing-box：Deno，约 1144 行，用 zod 校验输入，会转组和规则，但只认 9 种协议，任何一个节点不认就整份报错，样例和裁剪过的样例都没转出来。
  • clash2singbox：Go，一个 561 行的 main.go，2023 年归档，跟不上 1.12 以后的格式，没跑。
  • 值得借鉴：用 schema 严格校验输入。要避开：严格校验变成整份失败。
sing-box-subscribe分享链接转 sing-box，模板跟得比较新。
  • Python，parsers 下每种协议一个文件（含 anytls、hysteria2、tuic、wg），另有 clash2base64。模板有 sb-config-1.12.json 和 1.14.json，全部用 rule_set，没有 geosite 字段。
  • 仓库没有许可证，默认保留所有权利，代码一行都不能用，只能看模板结构。
在线站点怎么判断的看页面标题、前端打包里的仓库名和后端地址，再请求后端的 /version。
  • sub-web.wcc.best 和 amyconvert.com 的打包里写着 CareyWang/sub-web；api.wcc.best/version 返回「subconverter v0.9.0 backend」。sub.v1.mk 的打包里写着 youshandefeiyang/sub-web-modify，后端是 subapi.v1.mk/sub.php。
  • sublink.dev 页面的参考文档链到 tindy2013/subconverter，后端 api.sublink.dev 有 Cloudflare 拦截，查不到版本。sub.haitunt.org、subboost.org、scripthub.vercel.app 页面直接链着各自的仓库。
  • 闭源后端改了什么无法从外部确认，只能说是 subconverter 一系。sub.dler.io 拒绝连接、nexconvert.com 返回 403，这两家没查到。

推荐方案

用 Rust 自建，不嵌入现成转换器，也不只支持 sing-box 原生订阅。

  • 不打包 subconverter：GPL 程序作为独立二进制随附是允许的，Zephyr 现在就这样带着 mihomo。但它的 sing-box 输出在 1.12 以后加载不了，还会丢掉用户的组和规则，修它等于重写。
  • 不跑 Sub-Store：要额外带一个 Node 运行时，AGPL，而且只解决节点这一层。
  • 不只支持 sing-box 原生订阅：机场主要发 Clash 订阅和分享链接，只认 sing-box 订阅等于大部分用户切不了内核。
  • 自建的底子已经有了：crates/core/src/config/subscription.rs 里已有 Base64 判断、JSON Clash 解析、short-id 加引号（#2485、#2517），sanitizer.rs 有 YAML 和 JSON 两套危险键清理。

自建订阅转换模块

范围只是订阅转换：读进各种订阅，转成各个客户端和内核的配置。不做脚本、覆写、模块转换、私人订阅库。

架构

  • 新 crate zephyr-convert：纯函数，不做网络和文件读写，桌面端和以后的移动端、命令行都能用。
  • 输入层：识别格式（Clash/Mihomo YAML 和 JSON、分享链接、Base64 订阅、sing-box JSON，第二版加 Surge/Loon/QX 节点行），各自解析成中间表示。
  • 中间表示：节点（协议枚举、传输枚举、TLS/Reality、拨号选项）、策略组、规则（匹配条件和目标分开）、规则集、DNS。每个对象带一个「未识别字段」表，同格式往返时一个字段都不丢。
  • 输出层：每个目标一个模块，先查能力表（这个目标、这个版本支持哪些协议、传输、组类型、规则类型），再输出。sing-box 按 1.12、1.13、1.14 分版本。
  • 诊断：每次转换都返回一组诊断：哪个节点、哪个字段、是丢弃、近似还是不支持，界面直接显示。fallback 转成 sing-box 的 urltest 就是一条「近似」诊断。
  • 规则：GEOSITE、GEOIP 转成 rule_set，指向 MetaCubeX meta-rules-dat 的 sing 分支；Clash 的 yaml/text 规则集转成内联规则或本地编译 .srs；mrs 格式没有反向转换工具，报诊断。

和现有订阅导入怎么衔接

  • 现在桌面端的 normalize_subscription_content 依次做 Base64、JSON Clash、sing-box JSON 拒绝、分享链接列表原样保存、short-id 加引号后按 YAML 解析。
  • 把这几步挪进 zephyr-convert 的输入层，#2485、#2517 的测试原样跟过去，行为不变。
  • 用 mihomo 内核、订阅本来就是 Clash 时，照旧直接保存原文，不经过中间表示，避免引入回归。其他情况（sing-box 内核、分享链接、sing-box JSON 订阅）才走「解析、中间表示、输出」。
  • Zephyr 自己的设置（端口、DNS、TUN、模式、控制端口）在输出之后按内核分别叠加：mihomo 继续用 merge.rs，sing-box 新写一个叠加层，危险键清理复用 sanitizer.rs 的 JSON 版本。

「超越」怎么量化

和客户端集成都不知道客户端的设置按 Zephyr 设置生成端口、DNS、TUN，切内核自动重转

对比基准怎么搭

  • 样例：放在 crates/convert/tests/corpus，每份样例配一份「期望事实」（每个节点该有的字段值、组类型、规则数），全部假凭证。这次用的样例和打分脚本已经在本机 converters/bench 里，可以直接搬进去当起点。
  • 对手：bench/converters 下用固定版本跑 subconverter 分支（二进制）、Sub-Store（只调它的解析和输出函数）、Sublink Worker（只调它的 builder），都在本机跑，不用在线站点。
  • 打分：每份输出过 sing-box check（1.12 和最新版）和 mihomo -t，再和期望事实逐字段比，按上面的维度计分，生成一张对比表。
  • 进 CI：每个 PR 只跑 Zephyr 自己的样例加真内核加载，几分钟内完成；完整的多家对比每周定时跑一次，加上发版前跑一次；另有一个任务跟 sing-box 和 mihomo 的测试版，提前发现字段废弃。

实话：哪里能领先，哪里不值得

  • 能明显领先：完整配置转换、sing-box 版本正确、诊断、隐私、客户端集成、用真内核验证的测试。这些现有工具要么没做，要么做错。
  • 能追平：协议覆盖和主流目标的数量，工作量在上面的三个阶段里。
  • 代价大、不建议追：subconverter 的 ClashR、SSD、Mellow、旧版 Quantumult 等目标，对应的客户端基本没人用了；它的远程模板生态（ini 格式的组和规则模板）可以第三版之后再看要不要兼容。在线 URL 服务也不在客户端的范围内，需要的话可以出一个命令行工具。

长期维护

  • 字段一直在变：这次实测里 sing-box 1.12 删除了 geoip/geosite 数据库，1.14 删除了旧的 DNS 格式，subconverter 的输出就是这样失效的。
  • 控制办法：能力表按内核版本写；每加一个协议或字段先加样例；CI 跟测试版提前报错。估计平时每月 1 到 2 天，sing-box 发大版本时集中几天。

许可证

  • 可以：照 sing-box、mihomo 的官方文档和公开格式自己实现；读 GPL/AGPL 代码了解「有哪些字段、有哪些坑」，再自己写；自己写样例；在 CI 里跑 GPL 工具做对比（不分发）；MIT 项目（Sublink Worker、ConfigFlow、sub-web）可以拷代码，保留版权声明。
  • 不行：把 subconverter、Sub-Store、SubBoost、clash2sing-box 的代码逐段翻译成 Rust，这算衍生作品，会让 Zephyr 受 GPL/AGPL 约束，和 MIT 冲突；直接拷它们的测试样例文件也别做。sing-box-subscribe 没有许可证，同样不能拷。
  • 规则数据：meta-rules-dat 是 GPL-3.0，运行时按链接下载没问题；如果要把 .srs 打包进安装包，要按 GPL 附上许可和来源。
